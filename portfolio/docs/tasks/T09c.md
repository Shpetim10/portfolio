TASK T09c · Glyph Line Drawing ("Vitruvian Man, traced in code") · Roles: Motion Engineer + UI Engineer
Read: AGENTS.md, docs/design-system.md

GOAL
A component that renders Leonardo's Vitruvian Man as a line drawing: the square and
circle are drawn by code as exact vector hairlines, and the figure is traced in code
symbols that follow the direction of Leonardo's ink strokes. Driven by one progress
value (0→1) from the parent. The parent owns scrolling; this component only renders.
It must look clearly different from the dense marble mosaic of SymbolSculpture: sparse,
linear and precise.

INPUT
- assets-src/vitruvian/vitruvian-scan.jpg (cropped scan of the original drawing).
- assets-src/vitruvian/config.json (create with defaults; I will tune it in the lab):
  { "square": { "x": 0.17, "y": 0.10, "size": 0.66 },
    "circle": { "cx": 0.50, "cy": 0.47, "r": 0.40 },
    "navel": { "x": 0.50, "y": 0.47 },
    "inkThreshold": 0.42, "geometryMaskPx": 6,
    "colsDesktop": 96, "colsMobile": 60 }
  All values are normalized to the image (0–1). Leonardo centered the circle on the navel.

1 · BUILD-TIME TRACER — scripts/drawing/trace.mjs (sharp), npm script "drawing"
- Grayscale; remove the paper tone and stains with a large-radius background
  subtraction; apply an adaptive threshold so only ink remains.
- Mask out the ink of Leonardo's own square and circle (pixels within geometryMaskPx
  of the configured lines), so only the figure is traced. Code redraws the geometry.
- Sample into desktop and mobile grids (monospace cell ratio 0.6). Per cell store:
  ink coverage (0–255) and the dominant stroke direction from a Sobel gradient,
  quantized to 4 orientations (horizontal, vertical, diagonal /, diagonal \),
  plus a "crossing" flag where two orientations are both strong.
- Per ink cell store a formation order: distance from the navel, normalized 0–1
  (the figure radiates outward from the center of the circle).
- Output src/content/drawing/vitruvian.json (base64 arrays plus the normalized
  geometry), under 30 KB, and the FINAL glyph grid as plain text for both sizes,
  for the server-rendered fallback.

2 · GLYPHS (direction-aware)
- Horizontal strokes: - _ ─ ~ ; vertical: | ¦ │ ! ; diagonal /: / ⁄ ; diagonal \: \ ;
  crossings and dense ink: + x * # ; faint ink: . · :
- Alpha = 0.3 + 0.7 × (coverage/255). Color bone #EDE8DF on carbon. Martian Mono.
  Glyphs follow the stroke, so the figure reads as linework, not as a filled mass.

3 · RENDERING — src/components/drawing/GlyphLineDrawing.tsx
Props: data, progress (0–1), size ('desktop' | 'mobile'), onLayout?(anchors), className.
- Layers, stacked exactly: an SVG for the geometry (square and circle, 1px hairlines,
  vector-effect non-scaling-stroke, pathLength="1"), and the glyph layer for the figure.
- Server-render the final state: the SVG fully drawn plus a <pre aria-hidden="true">
  with the final glyph grid. On hydration, the glyph layer switches to <canvas> with
  identical size (no layout shift), glyph atlas, dirty-cell redraw, 30 fps cap, DPR ≤ 2,
  paused when off-screen.
- onLayout reports anchor points in container pixels: squareTopRight, squareTopCenter,
  circleBottomLeft, circleBottomCenter, navel. Re-report on resize.

4 · DRAWING SEQUENCE (driven by progress)
- 0.00 → 0.30: the square draws as one continuous line from its bottom-left corner,
  clockwise (stroke-dashoffset 1 → 0), in dust #8F8A80.
- 0.25 → 0.55: the circle draws from its bottom point, in both directions at once,
  meeting at the top, in dust.
- 0.45 → 0.95: figure glyphs appear in formation order (navel outward, ragged front:
  t = order × 0.85 + noise × 0.15). Each glyph fades in over 180 ms, with a single
  bright frame in bone at full alpha before settling, like ink touching paper.
- 0.95 → 1.00: a 4px signal-orange #FF4F00 dot appears at the navel. This is the only
  orange in the component.
- Fully reversible when scrubbing back.

5 · IDLE LIFE (precise and calm, never busy)
- A small bone point travels slowly around the circle (one revolution every 14 s),
  like a compass tip.
- Rarely (one cell every ~300 ms), a figure glyph swaps to another glyph of the same
  orientation. No particles.

6 · ACCESSIBILITY AND MOTION SETTINGS
- The SVG and glyph layers are aria-hidden; the parent supplies the figcaption.
- prefers-reduced-motion: server-rendered final state only; no loop, no compass point.
- Low device tier: mobile grid, 20 fps.

7 · LAB PAGE
- /lab/drawing: progress slider, size toggle, reduced-motion toggle, fps readout,
  and overlays for the configured square, circle and navel on top of the scan,
  so I can align config.json with Leonardo's lines.

ACCEPT
- Tracer output under 30 KB and identical on repeated runs.
- The code-drawn square and circle align with Leonardo's original lines within 1% of
  the image size (verify against the scan overlay in the lab).
- The figure reads clearly as line drawing at the mobile size; no paper stains or
  handwriting are traced.
- No layout shift between pre and canvas; under 4 ms main-thread time per frame
  at 4× CPU throttle; 0 ms off-screen.
- Report: files changed, screenshots at progress 0.3, 0.6 and 1, fps on the lab page.
