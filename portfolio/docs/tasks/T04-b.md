TASK T04b · Symbol Sculpture ("Victory, rebuilt in code") · Roles: Motion Engineer + UI Engineer
Read: AGENTS.md, docs/design-system.md
This replaces any earlier David version of T04b.

GOAL
A reusable component that renders a sculpture image as a grid of code symbols and
animates it assembling in the wind: the body forms first, the wings spread outward
last. Driven by a single progress value (0→1) from the parent. The parent owns
scrolling; this component only renders.

INPUT
- assets-src/victory/victory-base.png (black background, white marble figure facing
  left, wings sweeping to the right).
- assets-src/victory/config.json (create with defaults; I will tune it):
  { "core": { "x": 0.38, "y": 0.45 }, "windFrom": "left", "threshold": 28,
    "gamma": 0.85, "colsDesktop": 88, "colsMobile": 56 }
  core = normalized position of the torso center; windFrom = the side she faces.

1 · BUILD-TIME SAMPLER — scripts/sculpture/sample.mjs (sharp), npm script "sculpture"
- Grayscale, apply gamma, sample into desktop and mobile grids. Rows are derived from
  the image aspect and a monospace cell ratio of 0.6 (width/height).
- Per cell store luminance (0–255) and a figure mask (luminance > threshold).
- Per figure cell store a formation order: distance from the core point, normalized
  0–1 across the figure. The torso is near 0; the wingtips and the trailing drapery
  are near 1.
- Output src/content/sculpture/victory.json (base64 Uint8Arrays plus metadata),
  under 40 KB, plus the FINAL glyph grid as plain text for both sizes (fixed seed)
  for the server-rendered fallback.

2 · GLYPHS
- Code symbols only: . , : ; ' - _ = + < > / \ | ( ) [ ] { } * # % & @ 0 1 λ Σ Δ
- On mount, measure each glyph's ink coverage in Martian Mono on an offscreen canvas,
  sort by density, split into 8 buckets, and map luminance to a bucket.
- Color: bone #EDE8DF, alpha = 0.25 + 0.75 × (luminance/255). Background carbon.

3 · RENDERING — src/components/sculpture/SymbolSculpture.tsx
Props: data, progress (0–1), size ('desktop' | 'mobile'), paused?, className.
- Server-render a <pre aria-hidden="true"> with the FINAL glyph grid (Martian Mono,
  bone on carbon). It is the no-JS and reduced-motion state and must look complete.
- On hydration, swap to a <canvas> of identical size (no layout shift). Use a glyph
  atlas and drawImage per cell, redraw only dirty cells, cap at 30 fps, DPR ≤ 2.
- Pause when off-screen (IntersectionObserver) or when paused=true.

4 · ASSEMBLY IN THE WIND (driven by progress)
- Each figure cell's threshold: t = order × 0.85 + noise(col,row) × 0.15.
  The torso forms first, the wings sweep outward last, with a soft ragged front.
- progress < t → the cell is empty, apart from passing wind glyphs (below).
- As progress crosses t, the cell's glyph arrives as a particle: it starts 4–12
  columns away on the windFrom side, travels in a slight curve, and settles into
  place over 450 ms with settle easing cubic-bezier(0.16,1,0.3,1).
  Cap at 140 active particles on desktop and 40 on mobile. Beyond the cap, cells
  fade in over 200 ms instead.
- At the formation front, up to 4 glyphs may show signal orange #FF4F00 for a moment.
  This is the only orange in the component.
- Fully reversible: scrolling back makes glyphs drift away with the wind, never pop.

5 · IDLE LIFE (always moving forward)
- Settled cells re-roll within their density bucket at 0.3% per frame.
- Edge cells (figure cells next to the background) with order > 0.7, meaning the
  wingtips and trailing drapery, occasionally release a glyph: it drifts away from
  the windFrom side, fading over 1.2 s, and the cell re-forms. Keep it to about
  6–10 glyphs in flight at a time on desktop and 3 on mobile, so the edges feel
  windswept without the figure dissolving.

6 · ACCESSIBILITY AND MOTION SETTINGS
- Canvas and pre are aria-hidden; the parent supplies the figcaption.
- prefers-reduced-motion: keep the server-rendered final <pre>; no loop, no particles.
- Low device tier: mobile grid, no arrival particles (fade only), 20 fps.

7 · LAB PAGE
- /lab/sculpture: progress slider, size toggle, reduced-motion toggle, fps readout,
  and core-point overlay so I can tune config.json visually.

ACCEPT
- Sampler output under 40 KB and identical on repeated runs.
- No layout shift between pre and canvas; the final canvas frame matches the pre.
- The silhouette (both wings, drapery, stride) is unmistakable at the mobile size.
- Under 6 ms main-thread time per frame at 4× CPU throttle; 0 ms off-screen.
- Scrubbing back and forth is fully reversible with no leftover particles.
- Report: files changed, screenshots at progress 0.2, 0.6 and 1, fps on the lab page.
